4. 直っている点（そのまま）：親だけの条件は正しい（大阪府 × ○ ＝ 11,149 件、＋完パケ ＝ 63 件で DB と一致）。一覧の伏せ字、.mer の形式（cp932・CRLF・全項目引用符・日付 YYYY/MM/DD）、書き出しの記録、権限 403

## 2. 直すこと

### 2-1. 絞り込みの選択肢は実データから作る
- `GET /api/soil/list/options`（manager 以上）：選択式の項目（都道府県・AU光架電可否・購入状態・アポ禁）ごとに **実データの値と件数**を返す（`select 列, count(*) group by 列 order by count desc`、空は「（空欄）」として先頭）。サーバー側で 1 時間キャッシュ
- 画面はこの API の値でプルダウンを作る（固定の候補をコードに持たない）。件数を「大阪府（11,165）」のように添える
- **「空欄」を選べる**ようにし、条件は `op: "empty"`（IS NULL または ''）／`"notEmpty"` を追加する（アポ禁＝空欄 ＝ アポ禁なし）
- 都道府県の初期値は「指定なし」。初期条件は **都道府県＝指定なし・AU光架電可否＝○・アポ禁＝空欄** の 2 条件だけにする（押した瞬間に 0 件にならない組み合わせ）

### 2-2. 子表の条件を親の列に置き換える
- コール回数 → `コール回数合計`（範囲）、最終コール日 → `最終コール日_集約`（範囲）、購入履歴 → `購入履歴あり`（あり／なし）
- `applyChildFilters`・`fetchChildPhones`・`fetchPurchasePhones`・`CHILD_FILTER_PHONE_LIMIT`・`childLimitMessage` は削除。一覧の最終コール日・コール回数も親の列から
- 列の定義（list-fields.ts）に 3 列を足す

### 2-3. 送る形を揃える
- count／search／export／conditions すべて `{ condition: { filters }, ... }` に統一。画面も合わせる。テストも直す

### 2-4. その他
- 書き出しファイル名を `リストマスタ_YYYYMMDD_HHMM.mer`（日本時間）にする。Content-Disposition は RFC 5987（filename*=UTF-8''…）で日本語名を付け、ASCII の代替名も添える
- 「該当 ○ 件（○ 秒）」の表示は今のまま。5 秒を超えたときの「約」も今のまま
- 画面に開発者用語・絵文字を出さない。列名の直書きは list-fields.ts だけ
