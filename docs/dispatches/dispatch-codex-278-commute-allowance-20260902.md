## 1. 決めごと（支給額の求め方）

```
　支給額 ＝
　　　本人の申告 ≦ 上限        → 本人の申告
　　　本人の申告 ＞ 上限        → 上限
　　　上限が入っていない        → 空欄
　　　本人の申告が無い          → 上限をそのまま
```

「本人の申告」＝入社手続きの通勤区間の**1か月定期代の合計**（いまの `commuteTotals(...).passMonthly`）。

例：
- 申告 20,000 ／ 上限 15,000 → **15,000**
- 申告 12,000 ／ 上限 15,000 → **12,000**
- 申告 20,000 ／ 上限 なし → **空欄**
- 申告 なし ／ 上限 15,000 → **15,000**

## 2. 画面の絵

「事務が入れる」の交通費まわりを、次の3行にする。

```
　┌ 事務が入れる ────────────────────────────────┐
　│  …                                                    │
　│  交通費                                                │
　│    本人の申告（1か月定期代）    20,000円     ← 読むだけ        │
　│    交通費の上限（1か月・円）    [ 15,000            ]         │
　│    支給額（1か月・円）         [ 15,000            ] 自動計算   │
　│                              上限以下なら申告額、超えたら上限   │
　└────────────────────────────────────────┘
```

- **「本人の申告（1か月定期代）」の行を新しく足す。読むだけ。**
  本人が入れていなければ「未入力」と出す
- **「交通費の確定額」の名前を「支給額（1か月・円）」に変える**（欄そのものは今のものを使う）
- 支給額の欄の下に、小さく **「上限以下なら申告額、超えたら上限」** と添える
- **上限を入れたら（変えたら）、支給額を自動で計算して入れ直す**
- **事務が支給額を手で書き換えたら、そのあとは自動計算をしない**（その人の画面を開いている間）
- 並びは 上限 → 支給額 の順。**上限が先**（先に決めるものが上）

### いまの「あらかじめ入れておく」をやめる

`onboarding-admin.ts` の `adminInputFromRow` にある
「事務が未保存なら本人申告額を `commute_fixed_monthly` に入れておく」処理を**やめる**。
未保存のときは**空**のままにする。

代わりに、画面を開いたときに上限が入っていれば1章の計算で支給額を出す。
