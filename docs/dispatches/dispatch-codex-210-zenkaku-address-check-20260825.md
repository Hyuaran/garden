## 1. 郵便番号データの基盤（先にこれを作る）

「郵便番号データの運用」シートのとおり：

- **データ**: 日本郵便の公式データ（**読み仮名付き・UTF-8版**＝`utf_ken_all.zip`）。全国で約12万行
- **取り込み**: Garden が**月1回、自動でダウンロードして入れ替える**（Vercel cron。既存の `verifyBearerRequest`/cron の作法に合わせる）
  - 入れ替え中に判定が空振りしない方式にする（例：версию列や差し替え用テーブル。方式はCodex提案でよいが完了報告に書く）
  - 手動で今すぐ取り込めるやり方も用意する（初回投入と障害時用）
- **時点表示**: 前確依頼タブに「郵便番号データ：2026年8月1日 時点」のように出す
- **止まったときの警告**: 取込が**2か月以上更新されていなければ**、前確依頼タブに「郵便番号データが古い可能性があります」と表示する（判定は続ける）
- 注意（シート記載）: 「以下に掲載がない場合」等の特殊行がある／**1つの郵便番号に複数の町域**が対応することがある（複数候補のうちどれかに一致すればOKとする）

DBテーブルは新規（`supabase/migrations/`）。**SQL適用→読み取り確認→実機→マージの順**（先にマージすると本番が落ちる。厳守）。

## 2. 判定4本（R2-1〜R2-4・すべて「止めない指摘」）

`zenkaku-check.ts` の判定に追加し、`DEFERRED_ADDRESS_RULE_IDS` から外す。
**設置先と送付先の両方**を見る（送付先が空欄なら送付先側の判定はしない）。

| ルール | 内容 | 文言（Excel原文を使う） |
|---|---|---|
| R2-1 | 郵便番号から公式データを引き、**都道府県・市区町村**が一致するか | 郵便番号と住所が合っていないようです。ご確認ください。 |
| R2-2 | 公式データの**町域（大字）**が入力住所に含まれるか | 大字が抜けているかもしれません。ご確認ください。 |
| R2-3 | 公式データの**カナ**（市区町村カナ・町域カナ）と入力カナの照合 | 住所のカナをご確認ください。 |
| R2-4 | 郵便番号が公式データに**無い**（新住所の可能性があるため止めない） | この郵便番号が見つかりません。ご確認ください。 |

- 重要度は notices（「ご確認ください」枠）。**前確依頼は止めない**
- 判定は今までどおり**純粋な関数**側に足す（通信・DBに触らない）。郵便番号データの照合結果は
  API側で引いて判定関数に渡す形にする（判定関数の純粋さを保つ）
- 表記ゆれで嘘の指摘を出さないこと：全角半角・空白・「ヶ/ケ」等は正規化してから比べる。
  照合できない特殊行（「以下に掲載がない場合」等）は**指摘を出さない側**に倒す
- 指摘率の目安：過去の実測で約3.3%（多すぎる指摘が出たら正規化不足を疑う）
