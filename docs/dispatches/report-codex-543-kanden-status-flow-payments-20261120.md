# Codex-543 関電 ステータス・実績月・入金明細 実装報告

## 実装

- 事務入力は受付待ちを先頭に、諸元待ち・エントリー待ち・申込書待ち・郵送待ち・入金待ち・完了・キャンセル・保留・差し戻しを件数付きで表示する。案件一覧の進行中・完了・キャンセルも同じ優先順位で集計する。
- 実績月は空欄なら受注月を表示する。事務入力で実績月、申込書受取日、郵送日を変更できる。入金日と戻入日、照合済み明細の月・金額・区分・No. は事務入力と案件詳細で確認できる。
- 入金明細の取り込みは対象の Excel を読み、管理番号と契約品目で照合する。複数の受注が該当するなど、照合先が一意に決まらない行は理由付きで保存する。同月の同一 No. で内容が異なる場合は、どちらが正しいか判断できないため、保存前に取り込みを止める。
- 実績月の上書き、手動の保留・差し戻しを保持する。旧受注を郵送前キャンセルにした後で入金が見つかった場合は、明細を反映して判定し直す。
- 今回の PDF のみの月は **2024-01、2024-06、2024-08、2024-09、2024-10、2024-11、2024-12**。旧受注の入金が見込まれる翌月・翌々月に該当月が含まれる場合は要確認とする。

## 適用順

1. migration `20261120000543_leaf_kanden_status_flow.sql` を適用する。
2. `scripts/leaf-kanden-payments/import-statements.ts --dir <フォルダ> --dry-run` で対象件数と未照合理由を確認する。単一ファイルの場合は `--file <ファイル>` を使う。確認後に `--dry-run` を外す。分割保存が途中で失敗した場合は同じ入力で再実行し、取り込み完了後に次へ進む。
3. `scripts/leaf-kanden-orders/apply-timetree-labels.ts --file <JSON> --apply-legacy-cancel --dry-run` で旧受注の件数を確認してから、`--dry-run` を外して適用する。TimeTree ラベルと旧受注の振り分けは個別にも実行できる。

両スクリプトとも、このワークスペースでは `node node_modules/jiti/lib/jiti-cli.mjs <スクリプト> <引数>` で起動できる。件数確認にも Supabase の接続設定が必要。
