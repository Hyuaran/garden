# Codex-425：「掲載管理」を新設（タブ＝バイトル）し、掲載を期間で登録して期間中だけ自動で取り込む（2026-10-24）

## 目的
**【置き場所の変更・東海林さん 2026-10-24】** 採用管理の中のタブではなく、Sprout に**「掲載管理」という画面を独立させて**左のサイドバーに出す（**並びは「掲載管理」→「採用管理」**の順）。掲載管理はタブ式で、最初のタブは「バイトル」だけ（今後インディードなど媒体が増えたらタブを足す作り）。今「採用管理」にある「バイトル取り込み」タブは採用管理から外し、中身（取り込みの設定・取り込みの記録・再送）を掲載管理＞バイトル へ移す。
- URL：`/sprout/postings`（掲載管理）。採用管理は今のまま `/sprout`。
- サイドバー（`src/app/sprout/sprout.tsx` の左メニュー）を 2 項目に：掲載管理（上）・採用管理（下）。共通のシェル部分は 2 画面で使い回せるよう部品に切り出す。
- 見出し・場所の表示：「Sprout ／ 掲載管理」、タブ［バイトル］。

Sprout ＞ 採用管理 ＞「バイトル取り込み」タブ（Codex-422 で作成）の「取り込み：動かす／止める」の手動スイッチを、**掲載の登録（期間＋掲載内容）**に置き換える。
- 掲載期間に入ると自動で取り込みが動き、最後の日を過ぎると自動で止まる（止めるボタン不要）。
- バイトルは同時に複数掲載することがあるので、掲載を複数登録できる。どれか 1 つでも掲載中なら動く。
- ホスト PC は 10 分おきに `GET /api/sprout/baitoru/ingest` で「動かしてよいか」を聞いている（`baitoruEnabled()`）→ この判定を「掲載中があるか」に変えるだけでホスト PC 側は変更不要。

## 画面の絵
```
掲載管理 ［バイトル］
┌ 掲載の登録 ─────────────────────────────────┐
│ 掲載期間 [日付 2026-11-01] ～ [日付 2026-11-14]                     │
│ 掲載内容 [テレマアルバイト ▼]                         ［掲載する］ │
└────────────────────────────────────────┘
掲載の一覧（DataTable・新しい順）
 状態    掲載期間                  掲載内容          操作
 掲載中  2026-11-01 ～ 2026-11-14  テレマアルバイト  ［今すぐ終える］
 予定    2026-11-15 ～ 2026-11-28  テレマ正社員      ［取り消す］
 終了    2026-09-22 ～ 2026-10-05  テレマアルバイト  ─
┌ 掲載内容の選択肢 ─ テレマアルバイト ✕ ／ テレマ正社員 ✕ ／ [追加する文字] ［追加］ ┐
（今の「取り込みの設定」の囲みから「動かす／止める」「掲載期間の開始日」「通知のタイトル」を外す。残す＝除外する問合せ番号・通知先・メンション・1 回の上限）
```
- 日付は `<input type="date">`（カレンダー）。状態は日本時間の今日で決める：今日 < 開始＝予定、開始 ≤ 今日 ≤ 終了＝掲載中、終了 < 今日＝終了。［今すぐ終える］は終了日を昨日にする（記録は残す）。［取り消す］は予定のものだけ削除。
- 見た目は既存の Sprout と同じ社長スタイル。

## やること
1. migration `supabase/migrations/20261024000007_sprout_baitoru_postings.sql`：
   - `sprout_baitoru_postings`（id uuid・start_date date・end_date date（start ≤ end）・content text・created_at・created_by・ended_early_at）
   - `sprout_baitoru_settings` に `content_options text[] not null default '{テレマアルバイト,テレマ正社員}'`
   - 既存の 9/22〜10/5 の掲載を 1 行入れておく（テレマアルバイト・終了）
   - RLS：super_admin のみ select/insert/update/delete
2. 判定 `src/lib/sprout/baitoru.server.ts`：
   - `baitoruEnabled()`＝今日が期間内の掲載があるか（日本時間）。`settings.enabled` 列は使わなくする（列は残してよい）。
   - 重複判定の掲載期間の開始日＝掲載中のもののうち最も早い開始日（掲載中が無いときの dry-run は直近の終了した掲載の開始日）。
   - 通知のタイトル＝`【バイトル新規応募】{掲載内容} {M/D}～{M/D}`（掲載中が 2 つ以上なら掲載内容を「・」でつなぎ、期間は最も早い開始～最も遅い終了）。
3. 画面：`src/app/sprout/postings/page.tsx`（新設・super_admin のみ・それ以外は「準備中です」）に上の絵。`baitoru-panel.tsx`・`baitoru-actions.ts` は掲載管理側へ移す（採用管理の画面からは外す）。
4. テスト：状態の判定（境界の日・日本時間）、複数掲載、今すぐ終える、取り消しは予定だけ、enabled 判定、開始日・タイトルの作り方、super_admin 以外は不可。
