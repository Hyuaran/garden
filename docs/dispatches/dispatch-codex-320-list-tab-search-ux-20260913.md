## 1. 絞り込みの枠

- 右上の「10 項目」を消し、同じ位置に **［条件を保存］**（`secondaryButton` の見た目）
- 下の行（条件名の入力枠・「条件を保存」ボタン）と、その下の「保存した条件」セクションを**無くす**（機能はモーダルへ移す）
- **［検索］** を購入履歴の右隣（同じ行の右端）に置く。ラベルは「検索」。今の「件数を見る」（件数＋先頭の一覧を取る `handleCountAndSearch`）をそのまま「検索」にする。Enter でも検索できるとよい（入力欄で Enter）

## 2. 条件を保存のモーダル

- ［条件を保存］で開く。`createPortal(…, document.body)`・背景を押す／×／Esc で閉じる・開いている間は後ろを操作できない
- 上：条件名の入力＋［保存］（空なら押せない）。保存は今の `POST /api/soil/list/conditions`。保存したら一覧に増え、入力を空にして「保存しました」
- 中：いまの条件を業務の言葉で 1 行（`describeFilters`：都道府県：大阪府・奈良県／AU光架電可否：○／アポ禁：なし／リスト名：〜を含む／投入日：〜 のように、指定のある項目だけ）
- 下：保存した条件の一覧（名前・保存した人・日時）。［読み込む］＝条件を絞り込みに入れてモーダルを閉じ、**そのまま検索を実行**。［削除］＝確認（「この条件を削除しますか」）のあと削除。削除の API が無ければ `DELETE /api/soil/list/conditions/[id]`（manager 以上・全員共有なので誰の条件でも消せる）を足す

### 5-1. 検索 API は DB 直結にする（8 秒制限・1,000 行上限を避けるため）
- 台帳は 267 万件あり、絞った結果 190 万件を「氏名で並べ替えて 5,000 ページ目」のような照会は REST（8 秒）に収まらない。**一覧の取得（`POST /api/soil/list/search`）は Supabase REST でなく PostgreSQL に直接つなぐ**
  - 新規 `src/lib/db/pg.ts`：`pg` の `Pool`（`max: 1`・`ssl: { rejectUnauthorized: false }`・`connectionString: process.env.DATABASE_URL`・`statement_timeout` は接続後に `set statement_timeout = '60s'`）。**`pg` と `@types/pg` を依存に足す**（package.json・package-lock.json。ほかは触らない）
  - `DATABASE_URL` は Claude が Vercel と .env.local に入れる（Session pooler の接続文字列。コードに値を書かない・ログに出さない）。無いときは「一覧を取得できませんでした（接続の設定がありません）」を返す
  - 条件 → SQL の変換は `_lib/query.ts` の `buildBasePhoneQuery`（PostgREST 用）と**同じ意味になる SQL**を作る関数 `buildSearchSql(condition, sort, page)` を `_lib/search-sql.ts` に新設（列名は `SOIL_LIST_COLUMNS`・値はすべてプレースホルダ `$1, $2…`・`in`／`inOrEmpty`／`empty`／`notEmpty`／`contains`（`like '%…%'` の `%` `_` はエスケープ）／`gte`／`lte`／`eq`）。**テストで PostgREST 版と同じ条件が同じ行を返す**ことを、モックでなく「同じ条件の組」で確認する（少なくとも既定条件・大阪府＋奈良県・inOrEmpty・contains の 4 パターンの SQL 文字列とパラメータをスナップショット）
  - 並べ替え：`order by <列> asc|desc nulls last, "電話番号" asc`（列は許可リストから選ぶ。文字列を直接つながない）／ページ：`limit 100 offset (page-1)*100`
  - 件数は今の `POST /api/soil/list/count` のまま（変えない）
- `search` の返り値：`{ ok, rows, page, pageSize: 100, sort: { key, direction } }`。`toSearchRow` はそのまま使う（伏せ字の処理を変えない）
