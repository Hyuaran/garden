## 東海林さんの指示（2026-11-24・例＝受注日 2026/11/19 サイズディー）
1. 写メが「すべて」に 5 枚入っているが、電灯／動力／ガス／諸元／受領に分かれていないので見づらい
2. 申込コードは申込書の下に書いてある（例 0281-30101）。萩尾はこの番号で固定。まずは番号を集める。昔番号を整理したので、同じ営業でも過去の案件は違う番号のことがある
3. ステータスの帯（今は四角のカード 6 枚）を、Garden スタイルの見本のような**矢印の四角**にする。**先頭に「受注」を足す**。各ステップの下に「受注日」「諸元回収日」のような説明は書かず、**済んでいなければ「諸元待ち」、済んだら「諸元回収OK」だけ**。右のステップも同じ
4. 営業の帯は「PD番号　獲得営業担当　社員番号　部署　申込コード」の順。**受注日は帯から外す**（ステータスの帯の「受注」に出るため）。**PD 番号を営業担当より前**に
5. 検索は PD を付けても付けなくても当たる（PD1617124 でも 1617124 でも）

### B. 営業の帯（EntryScreen.tsx 410 行目あたり）
- 並び＝**PD番号**（`PD` ＋管理番号・枝番付き）／獲得営業担当／社員番号／部署／申込コード。受注日は消す
- 獲得営業担当を Root の従業員につなぐ：受注の `sales_name` は「萩尾」「萩尾拓也」、「辻󠄀」（異体字セレクタ付き）のように揺れる。異体字セレクタを外し、姓だけでも Root の在籍者に 1 人だけ当たればその人にする（2 人以上なら空のまま）。つながったら社員番号・部署を出す
- 申込コード：表 `leaf_kanden_sales_apply_codes`（root の従業員 id または sales_name の名前・申込コード・開始日・終了日・メモ）を新設（migration は書くだけ）。案件の `application_fields.apply_code` があればそれ、無ければ営業担当の申込コード（受注日で期間を当てる）を表示。初期値は migration で 萩尾拓也＝0281-30101（開始日は空＝ずっと）。RLS は事務入力を開ける人が読める・書き込みは service_role
- 帯の申込コードが営業の既定から来たときは、見本の「リスト」の値と同じ扱い（欄の 📋 で写せる）でよい
