# Codex-538 顧客一覧の「条件分岐処理プラグイン」30 ルールを Garden のしかけに移す（2026-11-20）

## 背景
顧客一覧（Kintone アプリ 10）では、Kintone の「条件分岐処理プラグイン」が 30 個のルールで値を自動で書き換えている。Garden の `public/kintone/garden-jisseki-rules.js`（Codex-536・実績日／実績可否）とぶつかる所がある（例：ルール 9「立ち上げ日が今日以前なら実績可否＝可」が、Garden の「後確OK日なしのキャンセル＝否」を上書きしうる）。
東海林さん決定：**条件分岐処理プラグインをやめて、Garden で管理する**。全ルールを Garden のしかけに移し、確かめたらプラグインを無効にする（無効化は Claude がやる）。

- ルールの一覧（正本）：`C:\Claude\000_Garden\060_Leaf_個別アプリ\02_全案件一覧の最新化\2026-11-20_顧客一覧の実績日の直し\条件分岐処理プラグイン_ルール一覧_20261120.md`
- 元の設定ファイル：同じフォルダの `条件分岐処理プラグイン_設定_20261120.json`

## やること
1. 新しいファイル `public/kintone/garden-kokyaku-rules.js`（配信 URL `https://garden-os.net/kintone/garden-kokyaku-rules.js`・アプリ 10 の PC／スマホ用）。書き方は `garden-jisseki-rules.js` と同じ（説明コメント・即時関数・純粋な関数を `module.exports`・`kintone` が無ければ return）
   - 純粋な関数 `applyKokyakuRules(values, today, loginUser)` → 変える項目だけの差分を返す
   - プラグインと同じく **項目の change のとき**に動かす（保存時には動かさない＝プラグインの設定が「保存時にも実行：しない」のため）。対象画面＝作成・編集（PC・スマホ）
   - 移すルール（番号は一覧の番号）：
     - 1・2・5・6 処理内容のチェック（項目コード `チェックボックス`）→ 処理区分ほか 6 項目を入れる／空にする
     - 3 トスアポ待ち、4 トス_パートナーコード（数値_0 ≥1 → パートナーコードへコピー。ルックアップは `lookup: true` で取得させる）
     - 7 入金待ち（開通日 ≤ 今日 かつ 工事種別 `ドロップダウン_39` が「新設」「新規・新設」「流用」以外 → 商材詳細ステータス・商材ステータス＝入金待ち）
     - 14〜17 ET者・決済登録者・後確者・開通前FC者（その日付＝今日 → ログイン中の人をユーザー選択に入れる。14 は `ET日カウント＿宮永テスト`＝〇も）
     - 18〜26 商材詳細ステータス → 商材ステータス の対応
     - 27〜30 カウント（日付が基準日以降 → 各「…カウント_宮永テスト」＝〇）
   - **移さない**：8・9（リトライ日・立ち上げ日 → 実績可否）は `garden-jisseki-rules.js` が受け持つ。10〜13（付与件数）は Garden の付与ポイント表から入れる別の仕組みにするので、今回は**入れない**（報告に「付与件数はプラグインを止めると自動で入らなくなる」と書く）
   - 「次のいずれかを含む」「次のいずれも含まない」「以前 TODAY」「等しい TODAY」「以降 日付」の意味はプラグインと同じに。今日は日本時間
2. テスト `public/kintone/garden-kokyaku-rules.test.ts`：ルールごとに 1 つ以上（とくに 3・7・14・18〜26）
3. `garden-jisseki-rules.js` は触らない（ぶつからないことをテストで確かめる：同じ入力で両方を順に当てても実績日・実績可否が jisseki の結果のまま）
