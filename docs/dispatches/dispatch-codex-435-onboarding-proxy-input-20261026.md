# Codex-435：入社手続きの代行入力＋「みんなの入社手続き」を行のどこを押しても詳細へ（2026-10-26）

## 目的（東海林さん 2026-10-26 決定）
1. **代行入力**：本人だけでなく、権限のある人が本人の代わりに入社手続き（本人の 11 画面）を入力・提出できるようにする。
   - 代行できる人＝**「みんなの入社手続き」タブを見られる人**（`canView("system-onboarding","all")`＝既定は責任者以上・歯車で変えた設定に従う）。
   - ただし**マイナンバーの画面と給与の受取口座の画面は全権管理者（super_admin）だけ**が代行できる。それ以外の人には、その 2 画面は「この画面は全権管理者だけが代わりに入力できます」と出して入力欄を出さない（中身も読ませない・サーバーでも拒否）。マスクされた値も出さない。
2. **「みんなの入社手続き」の表**：今は名前だけがリンク。**行のどこを押しても 1 人ぶんの詳細へ**行けるようにする。表は社長スタイルの `DataTable`（濃紺の見出し帯・見出し中央・並べ替え／絞り込み・検索「氏名・カナで探す」・行全体のホバー・Enter／Space でも開く＝Codex-429 の `onRowClick`）に。列は今と同じ（氏名・入社日・状態・未入力・事務入力）。
3. 1 人ぶんの詳細画面の見出し・場所の表示を「入社手続き（事務）」→「入社手続き」（場所の表示は System / 入社手続き / {氏名}）。

## 画面の絵
```
System / 入社手続き / 後道 愛美
後道 愛美さんの入社手続き                 ［本人の代わりに入力する］ ← 代行できる人だけに出る（提出前だけ）
（今の詳細＝本人の入力の確認・未入力の一覧・事務が入れる欄）

［本人の代わりに入力する］を押す →
┌────────────────────────────────┐
│ 代行入力中：後道 愛美さんの入社手続き（入力：東海林 美琴）［代行をやめる］│ ← 画面の上に固定の帯
└────────────────────────────────┘
 ■■□□□□□□□□□  全11画面のうち 2画面目   ← 本人と同じ 11 画面（OnboardingClient を代行モードで再利用）
 …
 給与の受取口座／マイナンバーの画面（全権管理者以外）：
   「この画面は全権管理者だけが代わりに入力できます」［次へ］
```

## やること
- 代行のページ（例 `/system/onboarding/admin/[employeeId]/proxy`）またはモードを作り、`OnboardingClient` をその人の分で動かす（本人の画面のコードを複製しない）。読み書きの API は対象の employee_id を受け取る代行用を用意し、**サーバーで** ①代行できる人か ②マイナンバー・口座の項目は super_admin か ③提出前か を毎回確かめる（ブラウザの出し分けだけに頼らない）。判定後の読み書きは管理者接続。
- 代行で保存・提出したら、誰が・いつ・どの画面を代行したかを記録（`system_onboarding` に `proxy_updated_by`／`proxy_updated_at` などの列、または記録用の表。migration は作るだけ・本番には当てない）。提出は「代行で提出（入力：○○）」と残す。
- 本人が同時に開いている場合は、今の途中保存のしくみと同じく後から保存した方が勝つ。代行中は本人の画面に何もしなくてよい（今回は通知しない）。
- マイナンバー・口座の項目：代行の API で super_admin 以外が送ってきたら 403。読み出しも super_admin 以外には返さない。
- 提出後は今と同じ（本人も代行者も直せない・事務の欄だけ）。
- `permission-registry.ts` に「入社手続き：代行入力」（既定＝みんなの入社手続きを見られる人／マイナンバー・口座は super_admin）を登録し、Root の権限一覧に出す。
- テスト：代行ボタンの出し分け（責任者＝出る・トス＝出ない・提出後＝出ない）／責任者は口座・マイナンバーを入力できない（API 403・画面に欄が出ない）／super_admin はできる／代行の記録が残る／みんなの表で行のどこを押しても詳細へ。
