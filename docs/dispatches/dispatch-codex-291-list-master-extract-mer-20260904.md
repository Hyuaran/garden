## 1. .mer の形式（027 が作った実物から確定）

- 文字コード **Shift_JIS（cp932）**、改行 **CRLF**、1 行目は列名、**全フィールドをダブルクォートで囲む**、区切りはカンマ
- 例（実物 `C:\Claude\027_リストマスタクリーニング\_整形出力\追加_購入リスト精査済み.mer`）：
  ```
  "電話番号","携帯番号","リスト名","リスト投入日","データ出所"
  "0664380375","","20250712_ヒュアラン社販売リスト0712","2025/07/12","購入リスト精査2026-08/株式会社Radish"
  ```
- 日付は `YYYY/MM/DD`。null は空文字。フィールド内の `"` は `""` に
- cp932 に無い文字（例：一部の環境依存文字）は `?` にせず **「〓」に置き換え、置き換えた件数を結果に出す**

- 絞り込みの項目は **設定で増やせる**ようにする（列名・表示名・入力の種類（選択／範囲／含む）を 1 か所の定義にまとめる）。最初の項目は上の絵のとおり
- 「件数を見る」は **正確な件数**を返す（索引で 0.1〜0.3 秒。5 秒を超えそうなら概算に切り替えて「約」を付ける）
- 一覧は 100 件まで。住所は市区町村まで、氏名カナは出さない（画面での個人情報の露出を減らす）
- 書き出しは上限つき（既定 5,000・最大 50,000）。並びを選べる。**書き出した行の電話番号は記録に残す**（誰に何を渡したか追えるように）

### 2-2. API（すべて manager 以上・service_role で読む）

| API | 中身 |
|---|---|
| POST /api/soil/list/count | 条件 → 件数 |
| POST /api/soil/list/search | 条件 → 先頭 100 件（伏せ字済み） |
| POST /api/soil/list/export | 条件＋列＋上限＋並び → .mer（Shift_JIS・CRLF）をそのままダウンロード。同時に記録を保存 |
| GET/POST/DELETE /api/soil/list/conditions | 保存した条件 |
| GET /api/soil/list/exports | 書き出しの記録（直近 50 件） |

- 条件は JSON（列・演算子・値の配列）。**SQL 文字列を組み立てない**（Supabase のクエリビルダーで `.eq/.gte/.lte/.ilike/.in` を使う）。列名は定義にある物だけ許可する
- 子表の条件（購入履歴あり／なし、コール回数）は親と結合せず、**子表で電話番号を先に絞ってから親に `.in`** する。件数が多いときは上限 1 万件までで打ち切って「絞り込みを増やしてください」と返す
- .mer は Node の `iconv-lite` で cp932 に変換（依存を足すときは package.json に書く）
