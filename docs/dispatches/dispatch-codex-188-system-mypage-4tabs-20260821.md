## 0. この作業のゴール（画面の言葉で）

社員が毎日使う入口を1か所にまとめる。いまバラバラにある「マイページ」と「勤怠打刻」を
**1つの画面の4つのタブ**にし、あとから「シフト」と「前確依頼」を足せる形にする。

```
マイページ ｜ 勤怠打刻 ｜ シフト ｜ 前確依頼
```

**この Dispatch は第1段階（器を作って中身を移す）だけが対象。**
第2段階（ダミーを本物のデータに）と第3段階（前確依頼の中身）は別 Dispatch で行う。

## 3. デザイン（現在のGardenに合わせる）

コール集計ポータル（`/system/call-metrics`）と**同じ配色変数**を使う。System内で見た目を揃えるため。

```css
--navy:#10233f; --heading:#10233f; --ink:#17212e; --sub:#5a6b80;
--teal:#0ea5a0; --teal-d:#0b7e7a; --blue:#2563eb;
--bg:#f5f8fc; --card:#ffffff; --line:#e3eaf3;
--shadow:0 10px 30px rgba(16,35,63,.08); --shadow-s:0 4px 14px rgba(16,35,63,.07); --r:22px;
```

- フォントは**ゴシック**：`"Meiryo","メイリオ","Hiragino Kaku Gothic ProN","Noto Sans JP",system-ui,sans-serif`
- **ダークモードでは見出し色を `--heading` で別に持つ**（濃紺のままだと背景に沈む。call-metrics で実測済みの是正）
- タブの見た目は call-metrics のタブに合わせる（選択中＝ティール）
- 現 `/tree/mypage` が使っている `GlassPanel` / `ActionButton` / `WireframeLabel`（Tree専用の部品）は**使わない**。
  System の見た目に置き換える。**中身の項目と並び順は変えないこと。**

## 4. 1タブ目「マイページ」の中身（現行そのまま）

現 `src/app/tree/mypage/page.tsx` の構成を、**この順のまま**移す。

| 順 | セクション | 項目 |
|---|---|---|
| 1 | 4桁ゲート | 「本人確認」。認証前はここだけ表示 |
| 2 | 基本情報 | 氏名／氏名カナ／社員番号／雇用形態／生年月日／メール／マイナンバー／交通費／給与受取口座 |
| 3 | 緊急連絡先 | 氏名／続柄／郵便番号／住所／連絡先 |
| 4 | パフォーマンス推移（6ヶ月） | ポイント／架電数／有効率／順位 |
| 5 | 提出・登録情報 | 緊急連絡先変更／通勤経路変更／退職届／秘密保持誓約書 |
| 6 | 設定 | パスワード変更／通知音／音量 |
| ─ | 定期確認バナー | 個人情報の定期確認中（3ヶ月に1度）／「変更なし」「変更あり」 |

### ★ダミーのまま移すもの（第2段階で本物にする）

現行はプロトタイプで、次は**全員に同じ値が出るダミー**である。**移設時に「準備中」と分かる表示にすること。**

- 緊急連絡先の5項目（現在「東海林 太郎」等が固定で出ている）
- マイナンバー「✅ 提出済み」／交通費「渋谷駅 〜 新宿駅」／給与受取口座
- パフォーマンス推移6ヶ月（2025/11〜の固定値）
- 通知音・音量（画面上だけで保存されない）

**やり方**：値の代わりに「準備中」と薄いグレーで出し、セクション見出しの横に
`（準備中：この欄はまだ本物のデータではありません）` と小さく添える。
**嘘の個人情報を本物のように見せない**ことが目的。

### 本物のまま移すもの
氏名／氏名カナ／社員番号／雇用形態／生年月日／メール／権限（`root_employees` から取得）。

## 5. 4桁ゲート（★本人の生年月日 MMDD に変更）

- 現行は `pw === "1234"` の固定。**これをやめる。**
- 正解＝**ログイン中の本人の `root_employees.birthday` の月日4桁**（例 1980-08-13 → `0813`）。
- **照合はサーバー側で行う**こと。クライアントに正解を渡さない
  （`/api/system/mypage/unlock` を新設し、入力4桁をPOST→サーバーで本人のbirthdayと照合→OK/NG だけ返す）。
- `birthday` が未登録の人は、ゲートを**通す**（入力欄を出さない）。ロックできないため。
  画面に「生年月日が未登録のため本人確認を省略しています」と出す。
- 画面の「デモ: 1234」の表示は**削除**する。
- 用途は「席を離れた隙の覗き見防止」（東海林さん）。ログイン自体が本人しか通れない前提の**二重の鍵の2つ目**。

## 7. 3・4タブ目「シフト」「前確依頼」

前確依頼   ：「準備中です。前確依頼の受付はもうしばらくお待ちください。」

- タブ自体は**押せる状態**にする（グレーアウトしない）。押すと上の文言が出る。
- 4タブ目は将来、営業IDを入力して［連携チェック］を押す画面になる（Gardenチェック14本）。
