## 1. 事務の画面への入口が無い（いちばん困っている）

いま左メニューの「入社手続き」は `/system/onboarding`（**自分の入力画面**）だけを指していて、
事務の一覧 `/system/onboarding/admin` へのリンクがアプリのどこにも無い。URLを直接打つしか行けない。

**メニューは増やさない。** 自分の入力画面の上に、責任者以上にだけ入口を出す。

```
　System ／ 入社手続き
　入社手続き
　┌────────────────────────────────┐
　│ [ みんなの入社手続きを見る（事務） ]              │ ← 責任者以上にだけ出す
　└────────────────────────────────┘

　（以下、今までどおり自分の入力画面）
```

事務の一覧側にも、戻れる入口を足す。

```
　System ／ 入社手続き（事務）
　入社手続き（事務）
　　　　　　　　　　　　　　　　　　　[ 自分の入社手続きへ ]
　┌──────────────────────────────────┐
　│ 氏名        入社日      状態      未入力   事務入力  │
　│ 吉田 陽菜   2026-09-01  提出ずみ   なし     未      │
　└──────────────────────────────────┘
```

- 責任者以上かどうかは、事務の画面と同じ判定（`MANAGER_ROLES`）を使う
- 責任者未満の人には**このボタンを出さない**（押せない見た目にするのではなく、出さない）
- ボタンの見た目は既存の `onboarding.module.css` に合わせる。**絵文字は使わない**

## 2. 「定期代の合計」が 0円 になる

本人が定期代を `20,000` とカンマ付きで入れると、合計が **0円** と表示される。
片道 `530`（カンマ無し）は正しく合計される。実データで確認ずみ。

原因は `src/app/system/onboarding/_lib/onboarding.ts` の `parseAmount`。
`/^[0-9]+$/` に一致しないものを 0 として扱っている。

**直し方**

- 金額の読み取りで、**カンマ（, と ，）・空白・全角数字**を取り除いてから数える
- 数字が1つも無いときだけ 0 とする
- **同じ問題が事務側にもある**：`src/app/system/onboarding/_lib/onboarding-admin.server.ts` の `numericText` も
  `/^[0-9]+$/` を使っていて、事務が「交通費の確定額」に `20,000` と入れると **null で保存されてしまう**。
  こちらも同じように直す
- 画面に入れた文字はそのまま残してよい（見た目は変えない）。合計と保存の値だけ正しくする

**テスト**：`20,000` / `２００００` / `20 000` / `20,000円` / 空 / `abc` を入れたときの合計と保存値。

## 3. 一覧の「入社日」が全員「未入力」になる

従業員台帳（`root_employees`）には入社日が入っているのに、事務の一覧では全員「未入力」と出る。
実データで確認ずみ（EMP-1559 は `2026-09-01`、EMP-0008 は `2020-01-01`）。

`src/app/system/onboarding/_lib/onboarding-admin.server.ts` の `readEmployees` が
ログイン中のユーザーの接続で `root_employees` を読んでいるため、行が返ってきていない。

**直し方**

- 事務の画面は既に「責任者以上」に限定されている（`onboardingAdminContext`）。
  そのうえで、**従業員の情報は管理者側の接続（`getSupabaseAdmin()`）で読む**。
  写真・動画・扶養控除申告書の用紙と同じやり方に揃える
- 取ってくる列は今までどおり `employee_id,name,hire_date,birthday,company_id` だけ。増やさない
- `deleted_at` が入っている人は除く（今までどおり）
- **権限の判定を緩めないこと**。`onboardingAdminContext` の責任者以上チェックはそのまま

**テスト**：一覧と詳細で、台帳の入社日が表示されること。

## 4. マイナンバーが画面の裏側に素で入っている

事務の詳細画面は `••••••••5540` と伏せて表示しているが、**そのページの中身（HTML）には12桁がそのまま入っている**。
本番の画面で実測して確認ずみ。伏せているのは見た目だけの状態。

マイナンバーは「必要な人だけが見る」「誰が見たかを記録する」が求められる情報なので、次のように変える。

### 4-1 画面には下4桁しか渡さない

- 事務の一覧・詳細に渡すデータは、**サーバー側でマスクしてから**渡す
  （`maskMyNumber` は既にある。本人画面 `onboarding.server.ts` と同じ扱いにする）
- **本人のマイナンバーと、扶養家族のマイナンバーの両方**が対象
- 扶養控除申告書のPDFを作る処理は、いままでどおり**サーバーの中だけで**全桁を使う（ここは変えない）

### 4-2 【マイナンバーを見る】ボタンを足す

```
　マイナンバー
　　マイナンバー（12桁）      ••••••••5540    [ 見る ]
　　　　　　　　　　　　　　　　　　　　　　　↓ 押すと
　　マイナンバー（12桁）      123456785540    [ 隠す ]
　　　　　　　　　　　　　　　　この画面を離れると、また伏せ字に戻ります
```

- 押したときだけ全桁を取りに行く（専用のAPI）。**最初の読み込みでは全桁を送らない**
- 責任者以上だけが使える。責任者未満には**ボタンを出さない**
- 「隠す」で伏せ字に戻る。**画面を再読み込みしたら伏せ字に戻る**（覚えておかない）
- 扶養家族のマイナンバーにも同じボタンを付ける
- 絵文字は使わない

### 4-3 見たことを記録する

- **記録先は既にある `root_audit_log`。新しいテーブルを作らない。SQLも書かない**
- 記録の書き方は `src/app/root/_lib/audit.ts` のラッパをそのまま使う
- 記録する内容
  - `action`: `my_number_view`
  - `target_type`: `system_onboarding`
  - `target_id`: 見られた人の社員番号
  - `payload`: `{ "kind": "self" }` または `{ "kind": "dependent", "index": 1 }`
- **記録にマイナンバーそのものを入れない**
- 記録に失敗しても画面は壊さない（既存のラッパの動きに合わせる）

## 5. メールアドレスを聞くようにする（新規）

本人のメールアドレスを入社手続きで回収する。いまはどこにも項目が無い。

**入れ物（列）はこの指示書と一緒に用意してある。**
`supabase/migrations/20260901000001_system_onboarding_email.sql`（`system_onboarding` に `email text` を足す）。
**Codex はこのSQLを本番に流さないこと。適用は人間側が行う。**

### 画面

「住所と連絡先」の**電話番号のすぐ下**に足す。

```
　住所と連絡先
　　郵便番号        [ 6360001 ]  [ 住所を出す ]
　　住所           [ 奈良県北葛城郡王寺町舟戸1-1-25            ]
　　住所のフリガナ    [ ナラケンキタカツラギグンオウジチョウフナト     ]
　　電話番号        [ 09054677653 ]
　　メールアドレス    [ hy.09054677653@docomo.ne.jp           ]   ← 足す
```

### 決まりごと

- 項目名は **「メールアドレス」**
- `TEXT_FIELDS` に `email` を足し、`FIELD_LABELS` に「メールアドレス」を入れる。
  「住所と連絡先」の段（`STEP_FIELDS`）に、`phone` の次として入れる
- **未入力でも提出できる**（他の項目と同じ扱い。未入力なら「未入力の項目」に出る）
- 入れ違いを防ぐため、**形が明らかにおかしいときだけ**その場に注意を出す
  （例：`@` が無い／`@` が2つ以上／空白が入っている → 「メールアドレスの形になっていません」）。
  **入力そのものは止めない**（保存も提出もできる）。判定を厳しくしすぎないこと
- 事務の詳細画面（読むだけのところ）にも「メールアドレス」を出す
- 伏せ字にしない（マイナンバーとは違う扱い）
- 入力欄は `type="email"` ではなく `type="text"` にする（ブラウザ標準の警告窓を出さないため）
