# Codex-545 関電：入金明細と受注の照合を直す（2026-11-20）

Codex-543・544 のあとに続けて行う。対象は `scripts/leaf-kanden-payments/import-statements.core.ts`（と .ts・テスト）だけ。

## 今の結果（Claude が本番の受注 18,975 件と明細 38 ファイルで dry-run）
読み取り 19,183 行のうち照合できたのは **2,633 行（14％）**。理由別：管理番号なし・不正 7,636／契約品目を判定できない 4,877／契約品目が合う受注なし 2,488／同じ管理番号の受注が 2 件以上 約 1,000／同じ管理番号の受注なし 568。

## 原因（実データで確認）
1. 明細の管理番号の形：`PD1234567`・`PD1234567動`（動力の行）・`PD1234567（2）`（枝番・全角かっこ）・`PD1234567（2）動`・`0792363566`（10 桁の数字だけ）・`-`（無し）。`動` が付くと normalizeKanriNo が null を返している
2. 受注側も `normalizeKanriNo` で **枝番 (2) を消している**ので、同じ番号の受注が何件も当たる。受注の kanri_no_raw には枝番が残っている（同じ kanri_no の受注が 2 件以上ある番号＝約 3,200）
3. 契約品目：`【奪還】ビジネス動力`・`【奪還】ビジネス電灯`・`【奪還】eおとくプラン`（ｅ全角もある）・`【奪還】なっトクでんき+なっトクプラン`・`【奪還】なっトクでんきBiz（ガス既契約の場合）`・`関電ガスのみ` など。eおとく・なっトクが判定できていない
4. 明細の **門標＝お客様番号（14 桁）**。受注の denki_customer_no（あり 18,348 件）・douryoku_customer_no（11,615 件）・gas_customer_no と同じ番号のはず。これが一番確かな鍵

## 直し方
- 明細 1 行の「種類」：契約品目か管理番号の末尾に「動力」「低圧電力」「動」→ 動力。「関電ガスのみ」→ ガス。それ以外（電灯・eおとく・なっトクでんき…）→ 電灯
- 明細の管理番号の鍵：全角→半角、末尾の「動」を外す、`PD` を外す、先頭 0 を外す、**枝番は残す**（`1234567` と `1234567-2` のように）。`-`・空は鍵なし
- 受注の管理番号の鍵：kanri_no_raw から同じ作り方（枝番を残す）
- 照合の順：
  1. 門標（数字だけにしたもの）が、種類に合うお客様番号（電灯→denki_customer_no、動力→douryoku_customer_no、ガス→gas_customer_no）と同じ受注。1 件ならそれ
  2. 複数あれば、その中で管理番号の鍵も同じもの。まだ複数なら、受注日が明細の送信日（sent_on）以前で一番新しいもの
  3. 門標で見つからなければ、管理番号の鍵（枝番込み）が同じで種類が合う受注（動力の行は動力申込ありの受注、電灯の行は電灯のある受注）。複数なら 2 と同じく受注日で 1 件に
  4. それでも決まらなければ order_id 空・match_note に理由
- dry-run の結果に「門標で一致」「管理番号で一致」「受注日で絞った」の内訳も出す
- テスト：上の管理番号の形すべて、種類の判定、門標優先、受注日で 1 件に絞る
