## 1. 何を作るか（画面の言葉で）

1. **ライト/ダーク切替ボタン**: マイページの右上、ログアウトボタンの**左**に、画面の明るさを
   切り替えるボタンを置く。押すたびにライト⇄ダークが切り替わり、次に開いたときも覚えている。
2. **重複警告を件数でまとめる**: 前確依頼タブで同じ営業IDが既に複数件あるとき、いまは
   「この営業IDは既に登録されています（…）。別商材の追加契約であれば、そのまま進めてください。」が
   件数分まるごと繰り返されて読みにくい。先頭に件数のまとめ1行＋明細を1件1行で出す。

## 2. ①ライト/ダーク切替ボタン

- テーマ機構は共通の ThemeProvider が全ページに入っている（`src/app/_lib/theme/ThemeProvider.tsx`）。
  `useTheme()` の `theme` / `toggleTheme` を使うだけでよい。保存（localStorage `garden.theme`）も
  DOM反映（`data-theme` と `.dark`）も Provider がやる。**自前で localStorage や documentElement を触らない**
- 置き場所: `MyPageClient.tsx` のヘッダー、`ログアウト` ボタンの左
- 見た目: ログアウトと同系のボタン（`mypage.module.css` に合わせる）。表示は
  「いま押すとどうなるか」が分かる文言（例: ライト時は「🌙 ダークにする」/ ダーク時は「☀️ ライトにする」）。
  文言は業務の言葉で（「テーマ」「モード」等の開発者語を前面に出さない）
- ダーク時の可読性: mypage.module.css の既存 dark ブロックの流儀に従い、ボタン自体も両モードで読めること
- 参考: `src/app/system/attendance/attendance-theme.test.ts` にテーマ切替テストの前例あり

## 3. ②R10重複警告の件数表示

- 現状: `zenkaku-check.ts` の R10 が重複1件ごとに warning を積み、`ZenkakuTab.tsx` がそのまま列挙
- 直し方（画面の結果）:
  - **2件以上**のとき:
    - 見出し1行「この営業IDは既に${n}件登録されています。別商材の追加契約であれば、そのまま進めてください。」
    - 続けて明細を1件1行（案件ID ／ 商材 ／ 登録日）
  - **1件**のときは現行文言のまま変えない
- **変えてはいけないこと**:
  - R10の判定条件（何を重複とみなすか）・警告の件数そのもの
  - `duplicateCount` の意味（投入時の「既に○件あります」確認に使われている）
  - サーバ側・常駐ブリッジ
- 実装方式（warning に構造化フィールドを足すか、表示側でまとめるか）は Codex 提案。
  判定14本のテストが全部緑のままであることを必ず確認し、方式と理由を完了報告に書く
