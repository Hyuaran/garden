## 本番で測った結果（Claude・Chrome・幅 1527px）
- `/leaf/kanden/entry` の最初の HTML が **5.5MB（展開後 7.4MB）・サーバー 3.7 秒・表示まで約 5 秒**。受注 約 1.9 万件を全部 HTML に入れて送っているため。
- `/leaf`（55KB・0.5 秒）・`/leaf/kanden`（61KB・0.3 秒）は軽い。
- 一覧の列は幅 180px なのに、中の表（管理番号・お客様名・受注日）が 436px → 横にはみ出し、お客様名が 1 文字だけ見えて受注日は見えない。


## やること
1. **送る量を減らす**（目標：最初の HTML 200KB 以下・2 秒以内で一覧が出る）
   - 最初は「今のタブ」の一覧だけ、1 ページ 50 件・一覧に要る列だけ（id・管理番号・お客様名・受注日・ステータス）を送る。並び替え・絞り込み・ページ送りはサーバーで
   - タブの件数バッジは、件数だけを返す集計（SQL の group by・RPC か view）で 1 回
   - 案件を選んだら、その 1 件の詳細・写メ・入金明細・変更履歴を取りに行く（Server Action か route）
   - 前へ／次へ・Ctrl+↑↓ は今のページの中で動き、ページの端なら次のページを読む
   - 検索（右上の管理番号・お客様名など）もサーバーで
2. **一覧の幅**：3 列の割合を `minmax(360px,1fr) minmax(420px,1.3fr) minmax(300px,1fr)` 程度にし、一覧の表が横にはみ出さないようにする（管理番号・お客様名・受注日が 1 行で読める。お客様名は長ければ「…」）。1280px 未満は「一覧＋入力」の 2 列で書類は下、900px 未満は 1 列
3. 表の決まり（社長スタイル §2.5〜2.7）：見出し中央・行全体を押す・縦線あり・行ごとに白/グレー・選んでいる行が分かる
4. 案件一覧 `/leaf/kanden` も同じ考え方か確かめ、全件を 1 回で送っているところがあれば同じように直す
5. テスト：ページ送り・件数集計・1 件の詳細の取得
