## 0. この作業のゴール（画面の言葉で）

コール集計ポータルの表示を3点直し、**Chatworkへ自動配信するときにPDFも一緒に届く**ようにする。
PDFは会議やホワイトボード掲示にそのまま使える形（A3縦）にする。

---

## 1. 画面の改善（3点）

### 1-1. 「時間ごとコール」を四捨五入して整数にする
- いまは小数第2位まで（例 `32.65`）。**四捨五入した整数**にする。
- 例：`10.5` → **`11`**／`10.4` → **`10`**
- 稼働時間が0秒以下のときは今までどおり `-`。

### 1-2. 見出しを「コール数/h」に変える
- 従業員ごとタブの見出し **「時間ごとコール」→「コール数/h」**。
- 定義方法タブの項目名も同じく「コール数/h」に変える（説明文はそのまま）。

### 1-3. 「社員名」の見出しだけ中央揃えにする
- いまは左揃え。**見出しのセルだけ中央揃え**にする。
- **中身（氏名）は左揃えのまま**。他の列の見出しは今までどおり右揃え。

## 2. Chatwork配信にPDFを添付（新設）

いまは文字のメッセージだけを送っている（`src/app/system/_lib/chatwork.ts` の
`sendCallReportMessage`）。**同じ配信で、集計のPDFも添付する。**

### 2-1. ファイル名
```
テレマコール集計ポータル_YYYYMMDD_HHMM.pdf
```
例：8/21 16時の配信 → `テレマコール集計ポータル_20260821_1600.pdf`
- 日時は**配信枠の正時**（既存の配信文面と同じ考え方。`call-report-schedule.ts` の判定に合わせる）
- タイムゾーンは日本時間

### 2-2. 中身（3部構成・A3縦）
| 順 | 内容 |
|---|---|
| 1 | **従業員ごと**（14列。画面と同じ並び） |
| 2 | **リストごと**（画面と同じ並び） |
| 3 | **定義方法**（集計の定義／休憩時間割／フラグ名の対応／結果フラグの扱い の4表） |

- **用紙はA3縦**（297×420mm）。A4横と横幅は同じで高さが2倍あるため、1ページに入る人数が増える。
- **固定の3ページではない。** 従業員が増えたり架電するリストが増えたら、
  **1部が2ページ以上に伸び、後ろの部がその分ずれていく**（自動でページ送り）。
- 各ページの上に「テレマ コール集計ポータル ／ 対象期間 YYYY-MM-DD〜YYYY-MM-DD」、
  下に「ページ番号／総ページ数」を出す。
- 表の見出し行は、ページをまたいだら**次のページでも繰り返す**こと。

### 2-3. 見た目
- **社長スタイル**に合わせる（下記3章）。
- 数字の列は右揃え、社員名・リスト名は左揃え。社員名の見出しは中央揃え（1-3と同じ）。
- トス数・受注数・前確OK数の **0 は薄いグレー**、1以上は黒の太字（画面と同じ）。

### 2-4. 作り方
- **`@react-pdf/renderer`（^4.3.1）を使う。**すでに依存に入っており、
  `src/app/bloom/monthly-digest/_lib/pdf-renderer.tsx` に実装例がある。新しいライブラリを増やさないこと。
- 日本語フォントの埋め込みが必要。monthly-digest の実装を確認し、**同じやり方に揃える**こと。
- PDFの生成は**配信の直前にサーバー側で行う**。ファイルはどこにも保存しない（送ったら捨てる）。

### 2-5. Chatworkへの送り方
- Chatwork API のファイル送信は `POST /rooms/{room_id}/files`（multipart/form-data）。
  `message` にこれまでの本文を載せられるので、**1回の送信で本文＋PDF**を届ける。
- 送信先ルームの決め方は既存と同じ（`CHATWORK_ROOM_KYOUYU_ID`、無ければ `CHATWORK_DEV_ROOM_ID`）。
- **PDFの生成や添付に失敗しても、本文のメッセージは必ず届くこと。**
  （PDFが作れなかったときは、本文だけを従来どおり送り、失敗をログに残す）
- 既存の `sendCallReportMessage` は残し、**添付つきの関数を別に足す**（呼び分けできるように）。

## 4. テスト

### 画面
- 「コール数/h」の見出しになっていること（「時間ごとコール」が無いこと）
- 四捨五入：`10.5`→`11`／`10.4`→`10`／稼働0秒→`-`
- 社員名の見出しが中央揃え、中身は左揃え
- 定義方法タブの項目名も「コール数/h」

### PDF
- ファイル名が `テレマコール集計ポータル_20260821_1600.pdf` の形式になること
- 3部が**この順**で出ること（従業員ごと→リストごと→定義方法）
- **従業員を1ページに入りきらない数にしたとき**、従業員ごとが2ページに増え、
  リストごと・定義方法が後ろにずれること
- 表の見出しが次のページでも繰り返されること
- ページ番号／総ページ数が入ること
- 0が薄いグレー、1以上が黒の太字であること

### 配信
- PDF生成に失敗しても**本文は届く**こと（失敗を差し込んだテスト）
- 送信先ルームの決め方が既存と同じであること
- 1回の送信で本文とPDFの両方が送られること

---

## 5. 完了時にやること

1. `npx tsc --noEmit` と対象テストが緑であること
2. **PDFを実際に1本、ローカルファイルとして出力する**こと
   - 出力先のパスを完了報告に書く（Chatworkへは送らなくてよい）
   - 生成が通ること・ページ数が期待どおりであることを確認する
   - ブラウザやPDFビューアを開いてのスクリーンショットは不要（画面とPDFの目視確認はこちら側で行う）
3. 完了報告をコードブロックで出力すること
   - 変更したファイル、PDFの出力先パス、ページ数、tsc/テストの結果を含める

## 6. やらないこと

- リストごとタブ・サマリー帯の列は変えない
- 配信の時刻や本文の文面は変えない（添付が増えるだけ）
- PDFの保存・履歴管理はしない（送ったら捨てる）
- 新しいライブラリを増やさない（`@react-pdf/renderer` を使う）
