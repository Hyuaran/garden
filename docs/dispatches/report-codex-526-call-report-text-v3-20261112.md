## 集計とクレカの獲得方法

配信の本文 v3（v1.16・2026-11-12）。【アウトテレマ】の従業員数は Root の current_team が宮永・小泉・石原・新人チームの人のうち当日コールのある人数（リーダー含む・上田とチーム無しを除く）。H は同じ四チームの KING OF TIME 当日実績 workMinutes の合計を時間へ換算して四捨五入した整数。平均コール数/人＝総コール÷人数、平均コール数/ｈ＝総コール÷H。取得失敗時は「-」と警告。コール履歴から算出した画面の稼働時間は代用しない。172回÷109ｈは四捨五入で2回（指示書の23回は計算と一致しないため式を優先）。受注数・受注率・前確OK率の数え方は従来どおり。

当日獲得ランキング1位は従業員別の当日 acquiredCount と tossCount で別々に決める。前確OKや受注への到達は条件にしない。同数全員を姓＋さんで「・」連結。0件の行は出さず、両方0なら見出しも出さない。

【テレマ全体】は顧客一覧app10の受注日が当日の自社・アライアンスと、クレカ8アプリ（既定66,84,89,91,94,96,229,230）。Soil付与ポイント表 soil_product_points の pointFor で獲得方法・商材・受注日の期間から合計付与Pを求める。resolveChannel はアライアンス優先、自社のリスト名WEB_はLP、他の自社は白地。内訳はコラボ／AU／クレカ／NURO／でんき／その他。0の内訳は省略し、合計0の獲得方法は括弧なし。不明商材は末尾に「⚠ポイント表に無い商材：商材名 n件」。商材ステータスがキャンセルなら除外（call-report-v3.ts の EXCLUDE_CANCELLED_REPORT_ORDERS 一か所で切替）。

クレカは管理表の safeFetchCredit・creditApps を共用する。管理表の従来の自社・OK・月次条件は維持。配信用は全フィールド・全件をページングして読み、日付_4（空なら紹介日）が当日の行だけ選ぶ。商材はドロップダウン_12（空なら商材名区分2）。事業名（管理表では文字列__1行__14が相当）とB_リスト名／リスト名があればresolveChannelで判定。獲得方法の欄が全て無い場合は白地。実アプリの欄の有無は本番を読まないため未確認。読めないアプリは「⚠クレカのアプリ <番号> を読めませんでした」、読めた分だけ集計して配信を継続する。

事業はLP事業マスタの回線・顧客アプリを利用し、ヒカリのプロ→電気お申込み受付窓口→フレッツ（顧客アプリ251）の順。電気開始受付センターは本文に出さない。発着信／初回応答率／対応顧客数／有効顧客率：x.x％（n件）／受注数（前確内訳）／前確OK率／記録なしがあるときだけ警告。有効顧客率＝有効顧客数÷対応顧客数（過去流入の顧客も含む）、分母0や未取得は「-」。事業ごとの受注率の行は出さない。受注は従来どおり受注日ベース。

配信時刻・0件スキップ・送り先・mode:test・PDF・ポータル画面は維持。新規cron・ポーリングは0回/日。既存の配信枠で追加取得：平日7回、土日祝11回。1枠あたりKOT2要求（当日実績＋従業員）、顧客一覧1系統、クレカ8系統、ポイント表1系統。1ページずつなら追加12要求/枠＝平日84・土日祝132要求/日。Kintoneは500件ごとのページ数、ポイント表は500行ごとのページ数に応じ増加し、KOTの既存リトライも別。手動preview/send/testの実行ごとにも同じ取得が増える。Storageへのアップロード・本番適用・外部送信は未実施。
