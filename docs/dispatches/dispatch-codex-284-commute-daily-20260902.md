いま「従業員台帳に反映する」を押すと、1日あたりの交通費を
**支給額 ÷ 20** で出している。これが実態と合っていない。

支払いの決まりは次のとおり（東海林さん）。

```
　社員（月給）　　　… 定期代で支給する（1か月まとめて）
　　　ただし長期欠勤などで数日しか出ていない月は
　　　　　　　　　　　 往復交通費 × 出勤日数 で支給する
　アルバイト　　　　… 往復交通費 × 出勤日数 で支給する
```

つまり **1日あたりの額は「実際の往復交通費」でなければならない。**
定期代を20で割った額では、実費と合わない。

吉田 陽菜さんの例：

| | いま | あるべき |
|---|---|---|
| 1日あたり | 15,000 ÷ 20 = **750円** | 片道530 × 2 = **1,060円** |

## 1. 1日あたりの出し方

```
　1日あたり（往復） ＝ 本人が申告した片道運賃の合計 × 2
```

- 「片道運賃の合計」は、いまある `commuteTotals(record.values.commute_routes).fareOneway` を使う
  （乗り換えがある人は区間ごとの片道を足した合計。吉田さんは1区間で530円）
- **片道が1円も入っていない人（自転車・徒歩など）は、1日あたりを出さない**

### 従業員台帳への反映

- `commute_daily_allowance` … **片道合計 × 2**（いまの `支給額 ÷ 20` をやめる）
- 片道が入っていない人は、**この項目を書き込まない**（今の「値が無ければ触らない」と同じ扱い）
- `commute_monthly_cap`（上限）と、そのほかの反映は**今までどおり**

**支給額（1か月）の決め方は変えない。**（上限以下なら申告額、超えたら上限）

## 2. 画面の絵

「事務が入れる」の交通費まわりを、次のようにする。**足すのは2行。**

```
　┌ 事務が入れる ──────────────────────────────────────┐
　│  …                                                          │
　│  交通費                                                      │
　│    本人の申告（1か月定期代）   20,000円      ← 読むだけ（今のまま）   │
　│    本人の申告（片道）          530円         ← 足す・読むだけ       │
　│    交通費の上限（1か月・円）   [ 15,000        ]                  │
　│    支給額（1か月・円）        [ 15,000        ]                  │
　│                              上限以下なら申告額、超えたら上限       │
　│    1日あたり（往復・円）       1,060円       ← 足す・読むだけ       │
　│                              欠勤などで数日だけ出た月と、           │
　│                              アルバイトの方は この額 × 出勤日数     │
　└──────────────────────────────────────────────┘
```

- **「本人の申告（片道）」**…片道運賃の合計。未入力なら「未入力」
- **「1日あたり（往復・円）」**…片道合計 × 2。片道が未入力なら「未入力」
- どちらも**読むだけ**。事務は直せない
  （直したいときは組織台帳（Root）側で直す。画面にその案内は出さなくてよい）
- 並びは上の絵のとおり。**1日あたりは支給額の下**
- 金額は `formatYen` など既存の出し方に合わせ、3桁区切りにする
