# Codex-419：入社手続きをトス・クローザーにも広げる＋最後に QR で公式 LINE 登録（使い切りの番号）（2026-10-24）

## 目的
設計書 C:\Claude\000_Garden\150_System_システム\02_入社手続き\004_設計_入社の流れの自動化_20261024.md の §3-2・§4（順番 C）。
入社日に会社のノート PC で事務が横について本人に入社手続きを入れさせ、提出後の画面の QR をスマホで読ませて公式 LINE「official｜通知」を登録させる。
登録の合言葉は、その人だけの**使い切りの番号**にして、なりすましを防ぐ。

## 画面の絵（提出後の画面の下に足す）
```
入社手続きを提出しました
（今の提出内容の確認はそのまま）
┌ 最後に、公式 LINE を登録してください ──────────────────┐
│  [QR コード 220px]   スマホのカメラで読み取ると LINE が開きます      │
│                                                                    │
│  開いたら、次の文をそのまま送ってください                           │
│        連携 1571-4K7P        ← 大きく・コピーできる                 │
│  ※友だち追加の画面が出たら、追加してから送ってください               │
│                                                                    │
│  （登録できると、ここが「登録できました」に変わります）              │
└─────────────────────────────────────┘
登録済みの人には：「公式 LINE は登録済みです（○○さん）」とだけ出す
```

## やること
1. **使い切りの番号**：表 `system_line_link_codes`（migration `supabase/migrations/20261024000002_system_line_link_codes.sql`）：employee_id、code（英大文字＋数字 4 桁・紛らわしい O/0/I/1 を除く）、expires_at（作成から 24 時間）、used_at、created_at。本人がこの画面を開いたときに有効なものが無ければ作る（API `GET /api/system/onboarding/line-link`＝本人の分だけ。返すもの：登録済みか・送る文・QR 用 URL）。RLS は本人の select のみ、書き込みは管理者側の接続。
2. **QR**：中身は `https://line.me/R/oaMessage/{LINE_STAFF_BASIC_ID}/?{送る文を URL エンコード}`（環境変数 `LINE_STAFF_BASIC_ID`、無ければ `@586gtqpd`）。QR の画像は npm の `qrcode`（人間がインストール済み）で SVG を作ってそのまま表示。
3. **登録できたかの表示**：画面を開いている間 5 秒ごとに `GET /api/system/onboarding/line-link` を見て、`root_employees.line_user_id` が入ったら「登録できました」に切り替え、確認を止める（10 分で止める）。
4. **受け口** `src/app/api/system/line/staff/webhook/route.ts`：「連携 1571-4K7P」（全角・空白ゆれも通す）を受けたら、番号と使い切りの番号が一致・期限内・未使用かを確かめ、一致したらその社員に紐づける（**すでに別の LINE と紐づいていても置き換える**＝ログインした本人が出した番号なので）。used_at を入れる。一致しなければ「番号が違うか、期限が切れています。入社手続きの画面に出ている文をそのまま送ってください。」。今の「連携 社員番号」（番号だけ）は当面そのまま残す。
5. **トス・クローザーにも入社手続き**：`src/app/login/page.tsx` の `ONBOARDING_REDIRECT_EXCLUDED_ROLES` から closer・toss を外す。ただし**今いるトス・クローザー全員がログインで入社手続きへ飛ばされないよう、入社日（root_employees.hire_date）が 2026-10-25 以降の人だけ**を対象にする（外注 outsource は今までどおり対象外）。トス・クローザーが `/system/onboarding` と必要な API を開けるか（ModuleGate・限定サイドバー・`src/lib/auth/permission-registry.ts`）を確かめ、開けなければ開けるようにする（他の System 画面は今のまま）。
6. テスト：番号の作成（期限・使い切り・紛らわしい字なし）、受け口の照合（一致・期限切れ・使用済み・別人の番号・置き換え）、トス・クローザーの対象判定（入社日で分かれる）、提出後の画面の表示（QR・送る文・登録済み）。
