## やること
1. **検索の置き場（slot）を外枠に作る**
   - 共通の部品（例：`src/app/system/_components/PageSearchSlot/`）に、置き場の要素を持つ Context と、置き場そのものの部品を作る。
   - 上の外枠それぞれで、右上のボタン列のすぐ下（右寄せ・幅はボタン列と同じ）に置き場を置く。置き場は空のときは高さ 0（何も無い画面で余白を作らない）。
2. **共通の表が検索をそこへ出す**
   - DataTable は、置き場があり、自分が**小窓（dialog）の中ではなく**、まだ誰も置き場を使っていないときだけ、検索の入力欄と解除ボタンを `createPortal` で置き場へ出す。それ以外（置き場が無い・小窓の中の表・2 つ目の表）は今どおり表の上に出す。
   - 置き場に出すとき、表の上の「検索」の大きな箱は出さない（`toolbar` のボタン類と `summary` は今どおり表の上の左に残る）。
   - 表が消える（タブを切り替える・画面を移る）と置き場は空に戻る。
   - 入力欄の `aria-label` は「この画面の中を検索」。薄い字は各画面の `searchPlaceholder`。
3. **スマホ（幅 800px 以下・外枠が上の帯になる幅）**：右上の空きが無いので、今どおり表の上に横いっぱいで出す（置き場は使わない）。
4. **ほかの部品が右上にある画面を崩さない**：例えば Root 従業員マスタ（`/root/employees`）はタイトルの行の右に歯車、その下に「従業員名簿最終更新」がある。置き場が歯車や「最終更新」に重ならないよう、外枠の段組みで場所を確保する（重なる画面があれば、その画面で置き場を歯車の左に寄せるなど、崩れない形にして報告に書く）。
5. **キー操作**：Root 従業員マスタの Ctrl+Shift+G（`src/app/root/employees/page.tsx` の `onSearch` が `tableRef` の中の `input[type=search]` を探している）が置き場の入力欄にも届くように直す。ほかに表の中の検索欄を探しているコードがあれば同じく直す。
6. **見た目**：入力欄は form-kit／globals の入力欄と同じ枠・角丸・明暗の色。ライト／ダークの両方で読めること。
