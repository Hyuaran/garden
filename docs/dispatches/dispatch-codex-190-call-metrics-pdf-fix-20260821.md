## 1. まず直すこと（表の文字が切れる）

### 症状
PDFの表で、見出しの最後の1文字が右端で欠ける。ほぼ全部の列で起きている。
（例：「コール数」の"数"が半分／「リスト受注率」の"率"が欠ける／「無効」「留守」「担不」も同様）

### 原因の見当
`src/app/system/_lib/call-metrics-pdf.tsx` の `VectorText` は、セルの幅（`column.width`）を
そのまま `<Svg width>` に渡している。一方セル側（`styles.th` / `styles.td`）には
左右 `paddingHorizontal: 3` と `borderRightWidth: 1` があるため、
**中身に使える幅はセル幅より 7pt 狭い**。その差の分が右端で切れている。

### 直し方
- セルの中で実際に使える幅を渡すこと（幅からパディングと罫線の分を引く）。
- そのうえで、**文字が幅に収まらないときは自動で小さくするか、収まる位置で折り返す**こと。
  見出しも中身も、**どんな長さでも欠けないこと**が条件。
- 特に **リスト名・社員名は長いものが来る**（例：`関西電力_20260801_再架電_A』`のような長い名前）。
  長い名前が来ても、切れっぱなしにせず読める形にすること。

## 2. 文字の描き方を元の方針に戻す（できる範囲で）

Codex-189 では、フォントを埋め込まずに **字形を図形（SVGパス）として描く** 方式になった。
指示は「`monthly-digest` と同じやり方（`Font.register` によるフォント埋め込み）に揃える」だった。

### やってほしいこと（この順で）

**(1) まず `Font.register` 方式を1回ちゃんと試して、失敗するなら「実際のエラー文」を完了報告に書くこと。**

- 使うフォントは **すでに `public/fonts/` にある `NotoSansJP-Regular.ttf` / `NotoSansJP-Bold.ttf`**
  （`monthly-digest` と同じもの。どちらも可変フォントではない普通のTTFであることは確認済み）
- 日本語は単語の切れ目が無いため、**折り返しの指定が要る**。
  `Font.registerHyphenationCallback` で1文字ずつ折り返せるようにする、等。
  これを入れずに「折り返せないから駄目だった」と結論を出さないこと。

**(2) それでも埋め込みが動かない場合のみ**、いまの図形方式のまま進めてよい。ただし条件付き：

- **`fontkit` を `package.json` の `dependencies` に明記すること。**
  いまは他のライブラリのおまけとして入っているものを借りている状態で、
  本番の依存解決で消えるとPDFが毎回失敗し、**本文だけが静かに届き続けて誰も気づかない**。
  これは絶対に直すこと。
- 自作の型定義 `src/types/fontkit.d.ts` は、正式な型が使えるならそちらに寄せる。
- 完了報告に「なぜ埋め込めなかったのか（実際のエラー文）」を必ず書く。
