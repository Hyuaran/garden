## 2. 画面 `/system/contracts`（2ステップ構成）

### ステップ1「上位店契約の登録」（保存漏れ防止が目的）

**入力は最小限にする。PDFから自動で読み取り「これでいいですか？」と確認させ、違えば直せる形にする**
（東海林さん指示2026-08-28・営業が入力を面倒がるため）。

- **操作は「PDFを選ぶ」だけ**。アップロードすると解析結果を確認カードに出す:
  - **甲**（相手先＝上位店）／**乙**（自社法人）／契約種別／締結日
  - すべて**編集可能なフォーム**として表示し、間違っていればその場で直して登録
- 自動抽出のルール（`pdfjs-dist` でテキスト取得後、空白を除去して判定）:
  - **甲・乙**: `（以下「甲」という）` `（以下、乙という）` 等の直前 30文字から社名を切り出す。
    表記ゆれ対応: 全角/半角括弧・「」/｢｣・`という。`/`という）`・読点あり/なし
  - **自社法人の特定**: 甲乙のうち **root_companies の会社名（7社）に一致した側を「乙＝自社」**とする。
    甲側に自社が入っていた場合は**甲乙を入れ替えずそのまま表示**し、画面に「自社が甲になっています」と注意を出す
  - **契約種別**: 1ページ目の見出し（`〜契約書` `〜覚書` `〜通知書` 等）を拾う
  - **締結日**: `令和N年M月D日` / `YYYY年M月D日` / `YYYY/MM/DD` を拾い、複数あれば**最も後ろのページ寄り**を優先
  - 抽出できない項目は**空欄にして「読み取れませんでした。入力してください」と表示**（エラーにしない）
  - **テキストが取れないPDF（スキャン画像）は全項目を手入力**にフォールバックし、その旨を画面に出す
    ※実測: 上位店28社のうち約7社がスキャン画像・甲乙の定義文が読めるのは文字ありPDFの約半数

- 保存先の `{相手先}` には**甲（上位店）の社名**、`{略号}` には**乙（自社法人）の略号**を使う
- 保存先: **`13_契約書\01_契約書　上位店\{相手先}_{会社略号}\`**
  - 会社略号は `company_id` から: COMP-001=HR / 002=CR / 003=LKS / 004=ART / 005=TIY / 006=ICHI / 007=SB。
    複数法人が対象のときは `ALL`（画面でALLも選べるようにする）
  - ルートフォルダIDは環境変数 **`GARDEN_CONTRACTS_DRIVE_ROOT_FOLDER_ID`**（値はClaudeが設定）。
    その配下の `01_契約書　上位店` を `findOrCreateSubfolder` で辿り、さらに `{相手先}_{略号}` を作る
  - 同名ファイルがある場合はファイル名末尾に `_YYYYMMDD_HHMMSS` を付す
- 登録後は一覧に出す（相手先・法人・種別・締結日・元PDFリンク・ひな形の有無）
- env 未設定時は保存をスキップして台帳だけ作る（届出PDFと同じ流儀）

### ステップ2「パートナー配布用ひな形の生成」

**この機能の本質は「甲乙の繰り上がり」**（東海林さん指示2026-08-28）:

```
元の契約（上位店と締結）      →   生成するひな形（パートナーへ巻く）
  甲 ＝ A社（上位店）                甲 ＝ 自社法人（元の乙がそのまま繰り上がる）
  乙 ＝ ヒュアラン（自社）            乙 ＝ 空欄（パートナー名を後で記入）
```
例: 元契約の乙がリンクサポートなら、**ひな形の甲はリンクサポート**になる。
→ ステップ1で確定した「乙＝自社法人」を、そのまま**ひな形の甲＝発行元**として使う（法人の選び直しは不要。
   ただし画面では変更できるようにしておく）。

一覧の行から「ひな形を作る」を押すと生成フォームへ:
- **隠す語句**（複数行・必須ではない）: 入力した語句を**全ページのテキストから探して白塗り**する
  （初期値として、その契約の相手先名を自動で入れておく）
- **金額を隠す**（チェック・既定ON）: `1,234円` `1234 円` のような**金額表記を正規表現で検出して白塗り**
  （「円」「¥」を伴う数字。ページ番号や条番号を誤爆しないよう、数字単独は対象にしない）
- **隠す語句の初期値**: 元契約の**甲（上位店）の社名**を自動で入れておく。
  あわせて root_companies に住所・代表者名があれば**上位店の住所・代表者名も候補として提示**（チェックで対象に追加）
- **発行元（＝ひな形の甲）の差し込み**: 既定は**ステップ1で確定した乙＝自社法人**（変更も可）。
  **1ページ目の指定位置**に `{会社名}` `代表取締役　{代表者名}` `{住所}` の3行を描画
  （NotoSansJP・右上寄せ・既定座標は上余白から40pt付近。座標は定数で持ち、後から調整できるようにする）
- **DRAFT透かし**（常時ON）: 全ページ中央に **薄いグレーの「DRAFT」**・**斜め45度**・大きく。
  文字色は不透明度0.15程度のグレー、本文が読める濃さにすること
- 生成後: **`13_契約書\05_パートナー配布用ひな形\{商材}\`** へ保存（`{商材}` は画面で入力・既定は契約種別）
  ＋ ブラウザにもダウンロードさせる。台帳の template_* を更新

### 生成処理の実装方針
- テキスト検出: `pdfjs-dist` でページごとに `getTextContent()` → 各アイテムの transform から矩形を算出 →
  一致した語句の矩形を白い矩形で塗る（`pdf-lib` の `drawRectangle`）
- 透かし: 全ページに `drawText('DRAFT', {rotate: degrees(45), opacity: 0.15, size: ページ幅に応じ算出})`
- 日本語描画は `@pdf-lib/fontkit` + NotoSansJP を `embedFont`
- **スキャン画像PDF（テキストが取れないPDF）**: 語句・金額の自動マスクは効かないため、
  **画面に「この契約書は画像のため自動マスクできません。透かしのみ付けます」と警告を出す**（生成自体は可能）。
  ドラッグでの手動マスクは**第2弾**（今回スコープ外）

## 4. テスト

- **自動抽出**（最重要・実データで検証すること）:
  - `株式会社ARATA（以下「甲」という。）とASH株式会社（以下「乙」という。）` → 甲=株式会社ARATA / 乙=ASH株式会社
    → **甲側が自社なので「自社が甲になっています」の注意が出る**
  - `Fado株式会社（以下「甲」という）と株式会社ヒュアラン（以下「乙」という）` → 甲=Fado株式会社 / 乙=株式会社ヒュアラン（自社）
  - `株式会社Crescere（以下「甲」という）と株式会社リンクサポート` → 乙=リンクサポート → **ひな形の甲＝リンクサポート**
  - 括弧・かぎ括弧・句読点の表記ゆれ4パターン以上
  - 抽出できないPDF（スキャン画像）は全項目空欄＋警告フラグ（エラーにしない）
- validate: 相手先・法人・種別・締結日・PDF必須／PDF以外を弾く／サイズ上限（20MBを超えたらエラー）
- 略号変換: COMP-001→HR 等の対応表・ALL 選択時
- Drive: フォルダ階層 `01_契約書　上位店\{相手先}_{略号}` を作って保存（Drive呼び出しはモック）・env未設定時スキップ
- 生成: 語句マスクで該当矩形が塗られる／金額正規表現が `1,200円` を拾い `第3条` を拾わない／
  透かしが全ページに入る／日本語の発行元3行が描画される／テキストなしPDFは警告フラグが立つ
- 既存の system / root 系テストが緑のまま
