## 1. 処理中の「くるくる」を全画面で出す（★一番大事）

### 何が起きたか
257件を一括完了 → 処理に時間がかかるのに**画面が何も変わらない**。
ボタンが押せていないのか、処理中なのか分からず、押し直しそうになった。
（押し直すと二重処理の危険もある）

### やること
**時間のかかる操作の間、全画面のオーバーレイ（くるくる＋文言）を出す。**
見本＝**スマホ申請の送信中画面**（`src/app/m/bud/submit/page.tsx`・#344）。
画面全体を覆い、くるくる（スピナー）＋「処理中です…」＋件数を出し、**閉じるまで他の操作をさせない**。

表示例：
```
（くるくる）
257件を完了にしています…
この画面を閉じないでください
```

### 対象の操作（すべて）
| タブ | 操作 |
|---|---|
| 完了待ち | **一括完了／一括差戻し**（発端。最優先） |
| 承認待ち | 一括系の操作があればそれも |
| 仕訳待ち | 仕分け情報を入力（複数件）／選択を削除 |
| 完了 | 弥生CSVを書き出す／台帳形式Excel（件数が多いと数秒かかる） |

- 処理が終わったら自動で閉じ、今までどおり結果メッセージを出す
- 失敗時も必ず閉じる（閉じ忘れて操作不能にならないこと）
- オーバーレイ表示中はボタンの**二重押しができない**こと
- 共通部品として1つ作り、各タブから使い回すこと（タブごとにバラバラに作らない）
- 進捗（n件中m件）が出せる処理は出す。出せない処理はくるくら＋件数だけでよい

## 2. 会社経費か個人経費かを一覧に出す

データには `expense_kind`（individual=個人経費／company=会社経費）が**全件入っている**のに、
一覧で分からない。ラベル関数 `expenseKindLabel`（`_lib/expense-kind.ts`）も既にある。

### やること
- **完了待ちタブ**の一覧・詳細に区分を表示する
- 承認待ち・仕訳待ち・完了・一覧タブでも、**出ていなければ**表示を足す
- **見せ方（Claudeの判断・違ったら報告に書く）**：
  個人経費が大多数（13,210 vs 195）なので、**「会社経費」のときだけ目立つバッジ**を出す。
  個人経費は無印（全行に「個人経費」と書くと紙面が埋まるため）
- 台帳形式Excel・弥生CSVの列は**変えない**（表示だけの話）

## 3. 申請者（人）で絞り込めるようにする

### やること
- **完了待ちタブ**に申請者の絞り込みを付ける
- 形式：**選択式（ドロップダウン）**。いまその一覧に居る申請者だけを選択肢に出す（全社員名簿を出さない）
- 「全員」が既定。絞り込むと件数カード・一覧がその人だけになる
- 一括完了・一括差戻しは**絞り込んだ結果に対して**働く（見えていないものを巻き込まない）
- 名簿にいない申請者（`applicant_name_text` だけの人）も選択肢に出ること

## 4. 変えないこと

- status の値・遷移（#460の新フロー）
- 一括完了・一括差戻しの処理そのもの（見た目と絞り込みだけ）
- 弥生CSV・台帳形式Excelの中身
- 仕訳待ちの人ごとのまとまり・バー固定（#461）
- 新しいライブラリを増やさない
