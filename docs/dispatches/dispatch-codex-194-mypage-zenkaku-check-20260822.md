## 0. これは何をするものか（画面の言葉で）

営業が前確依頼を出す前に、**入力の漏れ・間違いをその場で拾う**しくみ。呼び名は「**Gardenチェック**」。

```
営業IDを入力 →［連携チェック］→ FileMaker11 の営業マスタを確認
  → 漏れがあればその場で指摘（どこが足りないかを全部並べる）
  → OK なら Kintone の「取次連携用」と「全案件一覧」へ投入
```

**今回（第1段階）で作るのは、この線の中の「画面」と「判定そのもの」だけ。**
FileMaker を読む経路と、Kintone への投入は**次以降の段階**でやる（§6）。

## 3. 作り方（データの入り口は1つにまとめる）

FileMaker を読む経路は次の段階で作る。**今回はその境目をはっきり切っておくこと。**

- 判定は**純粋な関数**にする。「営業マスタ1件ぶんの値」を受け取り、「指摘の一覧」を返すだけ。
  画面・通信・DBに触らない。→ そうすれば、次段階で入り口が付いたときに判定側を触らずに済む。
- 営業マスタ1件ぶんの**型**を決める（Excelの「営業マスタ項目」シートの117項目が元。
  今回のルールが使う項目は必ず含める。使わない項目まで全部書く必要はない）。
- 画面からは、いまは**仮のデータを返す入り口**（モック）を通して判定を動かせるようにしておく。
  実際の FileMaker 接続は次段階。**モックを本番の経路に見せかけないこと**（画面には
  「まだ FileMaker とつながっていません」等は書かず、次段階で差し替わる形にしておく）。

## 4. テスト
