## 3. 稼働時間の計算式（新規実装）

**日ごとに計算して、期間内の合計を出す。**

```
その日の稼働時間 = （その社員のその日の最後のコール終了時刻）
                 −（その社員のその日の最初のコール開始時刻）
                 − （上記の範囲と重なる休憩時間の合計）
```

- 開始時刻 = `system_call_history.call_time`
- 終了時刻 = `system_call_history.call_ended_time`
  - **終了時刻が空の行は、その行の開始時刻で代用する**
    （実測：2026-08-19 は 3,032件中42件が空。開始時刻は全件入っている）
- 期間が複数日のときは、日ごとの稼働時間を足し上げる
- 稼働時間が0秒以下になった場合は `0:00:00` とし、時間ごとコールは `-` と表示する

### 休憩時間（6区分・合計120分）

| 開始 | 終了 | 長さ |
|---|---|---|
| 11:15 | 11:30 | 15分 |
| 13:00 | 14:00 | 60分 |
| 15:20 | 15:30 | 10分 |
| 16:45 | 17:00 | 15分 |
| 18:20 | 18:30 | 10分 |
| 19:50 | 20:00 | 10分 |

- **重なった分だけ引く**（部分的に重なる場合は重なった秒数だけ）
- 例：最初のコールが15:01なら、11:15〜11:30 と 13:00〜14:00 は範囲外なので引かない

## 7. RPC（PostgreSQL）側の変更

対象: `public.system_call_metrics`
最新版は `supabase/migrations/20260814000002_system_call_metrics_preconfirm_reattribution.sql`。
**新しいマイグレーションを1本足す**（既存ファイルは書き換えない）。

`employee_metrics` CTE に以下を追加して JSON に含める:

| 返す名前 | 中身 |
|---|---|
| `prospect_count` | `result_flag = '見込'` の件数 |
| `absent_count` | `result_flag = '担不'` の件数 |
| `away_count` | `result_flag = '留守'` の件数 |
| `invalid_count` | `result_flag = '無効'` の件数 |
| `work_seconds` | 上記3.の稼働時間（秒）。日ごとに計算して合計 |

稼働時間の SQL イメージ（考え方。実装は任せる）:

```sql
-- 日ごとの稼働幅
daily_span as (
  select employee_name, call_date,
         min(call_time) as first_start,
         max(coalesce(call_ended_time, call_time)) as last_end
  from ... group by employee_name, call_date
),
-- 休憩マスタ
breaks(b_start, b_end) as (values
  (time '11:15', time '11:30'), (time '13:00', time '14:00'),
  (time '15:20', time '15:30'), (time '16:45', time '17:00'),
  (time '18:20', time '18:30'), (time '19:50', time '20:00')
),
daily_work as (
  select d.employee_name, d.call_date,
    extract(epoch from (d.last_end - d.first_start))
    - coalesce((select sum(greatest(0, extract(epoch from
        (least(d.last_end, b.b_end) - greatest(d.first_start, b.b_start)))))
      from breaks b), 0) as work_seconds
  from daily_span d
)
```

- 既存の `call_order_rate` / `call_acquired_rate` は**残す**
  （リストごとタブと日報APIがまだ使っているため。従業員タブで表示しないだけ）
