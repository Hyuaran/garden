## 作るもの
1. **電子契約サービスの差出人の一覧**（classify.ts。後で足しやすい配列）：`moneyforward.com`（`contract.moneyforward.com` 含む）・`cloudsign.jp`・`gmosign.com`・`docusign.net`・`echosign.com`・`adobesign.com`・`ninja-sign.com`・`freee.co.jp`（sign を含むアドレスだけでよい）など。今の `ELECTRONIC_SENDERS` による一律の除外はやめる
2. **締結完了の知らせ**＝差出人が上の一覧で、件名に「署名完了」「締結が完了」「締結完了」「合意締結」「completed」のどれかがあるもの。**依頼・確認・再送の依頼・アカウント登録の案内は対象外**（件名の「依頼」「確認」「ご案内」で判定。「完了」が無ければ対象外でよい）
   - 除く言葉（雇用契約・誓約書・入社・退職）は今と同じに効かせる
3. **PDF が付いている締結完了の知らせ**：添付の pdf をすべて「契約書」（13_契約書）の候補にする（名前に言葉が無くても。合意締結証明書も一緒に）。中身（MD5）で保存済みかを見るのは今と同じ。自動保存（段階 2）の対象にもなる
4. **PDF が付いていない締結完了の知らせ**（添付なし・smime.p7m だけ 等）：status `"needs-download"`（電子契約のサービスから取り出しが必要）として知らせる。中身が無いので MD5 照合はしない
   - 知らせの節：「■電子契約（PDF が付いていない＝電子契約のサービスから取り出して 13_契約書 に保存してください）」。行＝受信日時・サービス名（差出人ドメインから：GMO サイン／クラウドサイン／マネーフォワード クラウド契約／DocuSign／Adobe Sign／freee サイン／その他はドメイン）・宛先の箱・件名
   - **同じ知らせを毎日出さない**：`needs-download` は「前回の本番の実行（applied かつ ok）より後に受信したもの」だけ知らせる。前回が無い（初回）は 45 日分すべて。`run.ts` の `previous`（lastApplied）の ran_at を judge に渡す形でよい。dry でも同じ基準で判定
   - counts に `needsDownload` を足す。知らせを送るかどうかの判定に `needsDownload` も入れる
5. 自動保存の「同じ中身は二度保存しない」・転送・古い版の扱いは変えない
