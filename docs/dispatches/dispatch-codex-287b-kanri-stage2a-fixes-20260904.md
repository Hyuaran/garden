## 2. 作るもの

### 2-1. 手入力の引き継ぎ（API）

- GET /api/system/kanri/inputs/[yearMonth]：その月の run のうち、**sheet='inputs' が保存されている最新のもの**（calculated_at の降順）を返す。最新の run に無くても、前の run にあればそれを返す
- PUT：保存先は今どおり「その月の最新の run」。保存後の GET が同じ値を返すこと
- POST /api/system/kanri/runs/[id]/calculate：手入力は「その run」ではなく **GET と同じ探し方**（月内の最新の手入力）で取る
- 画面：取り込み直後に手入力が消えないこと（importData の後の loadInputs で同じ値が戻る）

### 2-3. 答え合わせテストの厳格化

`src/app/system/kanri/_lib/calc/kanri-sheet.golden.test.ts` を次のとおり作り直す。

- 係数・単価は **付与ポイント.json（3 行目＝見出し、4 行目＝係数、5 行目＝単価）だけ**から取る。Excel の答え（4〜6 行目）から逆算しない。`unitPriceByTeamByProduct` は使わない（計算部品からも外してよい）
- 付与ポイント見出し → 管理表の商材名の対応表をテスト内に明示する（JCB Biz ONE→JCB、三井住友カード（NL）→NL、三井住友ビジネスオーナーズ（SMCCAV）→SMCCAV、セゾン（発行のみ）→セゾン、ライフカードビジネスライト→ライフ、三菱UFJニコス→UFJ、**さすがネット→さすガねっと**、ほかは同名）
- Kintone 表記の束ね（kintone_names）は **DB の初期値と同じ内容**をテスト内の表に持つ（C:\garden\a-bloom-008\supabase\migrations\20260903000001_system_kanri_portal_stage2.sql の insert と一致させる。テストから SQL を読まなくてよい）
- **Excel の癖 2 点は期待値側で補正**してから全セル一致にする（除外ではなく補正。理由をコメントに書く）
  1. Sofbank光 の金額（S6／AP6／BM6）：Excel は式が無く空。期待値を `件数 × 開通率 × 30,000` に置き換える
  2. 石原チーム ACマスター の金額（BT6）：Excel は `付与ポイント!R5`（16,000）を参照する 1 列ズレ。期待値を `BT4 × BT2 × 25,000` に置き換える
  3. 上の補正に合わせて、金額の合計（K6／AH6／BE6／G6）と時間あたり金額（I6／AF6／BC6／E6）の期待値も計算し直す
- 除外は BE5（+0.4 の手打ち補正）と、それに引きずられる BD5／F5／G5 だけ。除外理由をコメントに書く
- 失敗時のメッセージは今どおり「一致 ○セル／不一致 ○セル」と各セルの期待値・実際値
- 設定表に 20 商材（NURO光（7万CB）を含む）ある一方で管理表は 19 列。テストの商材の並びは **設定表（付与ポイント.json の見出し順）** とし、管理表に無い商材は件数 0・比較対象外にする
