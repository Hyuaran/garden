## 1. ダウンロードURLが404（★取込が動かない）

`JAPAN_POST_UTF8_URL = "https://www.post.japanpost.jp/zipcode/dl/utf/zip/utf_ken_all.zip"` は
サイト移転により **404**（実測。HTMLのエラーページが返る）。

### やること
正URLに変更（実測でzip 2.0MB・124,513行の取得成功を確認済み）：

```
https://www.post.japanpost.jp/service/search/zipcode/download/utf/zip/utf_ken_all.zip
```

- 旧URLは `.../zipcode/dl/utf-zip.html` → `.../service/search/zipcode/download/utf-zip.html` へ
  リダイレクトされるがzip本体は404のまま。**リダイレクト追従では救えない**ので定数を直す

## 2. カッコ書き町域で誤指摘が出る（★実測5.2%）

実データの町域には「大通西**（１〜１９丁目）**」のようなカッコ書きが **6,504行（5.2%）** ある
（カナ側も同様に「オオドオリニシ**（１−１９チョウメ）**」が6,338行）。
現状はカッコ込みのまま `input.includes(candidate)` で比較するため、
入力「大通西１丁目」に対して R2-2「大字が抜けているかもしれません」、
カナでも R2-3 の**嘘の指摘**が出る。

### やること
比較用の候補値から**カッコ以降を取り除いて**から比較する：

- 町域：「（」以降を除去（例：「大通西（１〜１９丁目）」→「大通西」）
- 町域カナ：同様に「（」以降を除去（NFKC正規化後なら半角 `(` に統一される点に注意）
- 除去後が空文字になった候補は町域・カナの照合対象から外す
- **取り込みデータ自体は原文のまま保存**し、比較時に除去する（zenkaku-check側）。
  こうすると将来表示に使うとき原文が残る

### 安心してよい点（実測済み・対応不要）
- カッコが行をまたぐ形式（SJIS版の有名な罠）はUTF版では **0件**
- 「利島村一円」等の「〜一円」特殊行は23件で、既存の `is_special` 扱いで安全側
- 完全重複行が156行あるが実害なし
