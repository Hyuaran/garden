# Codex-539 顧客一覧の付与件数を Garden の付与ポイント表から反映

## 実装

- `GET /api/kintone/product-points` は、商材・マスタ商材・事業名・リスト名・判定日を受け取り、付与ポイント・表の商材名・獲得方法を返す。許可する CORS オリジンは顧客一覧の Kintone ドメイン。入力エラーは 400、表を取得できない場合は 503。同じ問い合わせは Vercel で5分キャッシュし、再検証中は最大10分古いキャッシュを利用できる。サーバーのポイント表も取得完了から5分保持し、同時の読み取りをまとめる。
- `garden-fuyo-points.js` はアプリ10の PC・スマートフォンの作成・編集画面で、対象項目の変更時と保存直前に付与件数を取得する。実績日を優先し、空欄なら受注日を使う。商材名区分2で該当行がなければ m_product を照合する。表に該当行がない場合は現在値を維持して画面上部に案内を出す。保存時の取得は5秒で打ち切り、現在値のまま保存を続ける。
- 既存受注の確認・反映スクリプトを追加した。対象は実績日が `--from` 以降のレコード。開始時点の対象レコード番号の上限を取得し、500件ずつ読み取る。全対象の比較 CSV と件数を出力し、`--apply` 指定時に変更対象だけを100件ずつ更新する。読み取ったリビジョンを指定し、競合や通信失敗で停止する。外部通信は1回15秒、全体で15分を上限とする。
- Garden の付与ポイント表は、保存成功後に Kintone 側へ反映されるタイミングを表示する。

## Vercel 呼び出しの見積もり

1日500件の保存、1件につき対象項目の変更で平均2回の照会と仮定すると、GET は `500 × (2 + 1) = 1,500 回/日`。Vercel の関数実行はこのうち CDN キャッシュを利用できないリクエストと再検証が対象になる。同じ問い合わせが再利用されない場合の目安は1,500回/日。通常の照会はカスタムヘッダーを付けない GET なので OPTIONS は発生しない想定。cron・定期照会・一括反映からの Vercel API 呼び出しは0回/日。

## Claude への引き継ぎ

アプリ10の PC・スマートフォンに `https://garden-os.net/kintone/garden-fuyo-points.js` を登録する。保存時に更新された実績日を参照できるよう、`garden-jisseki-rules.js` の後に配置する。動作確認と条件分岐処理プラグインの停止は Codex-538 と調整する。

一括反映は、先に `npx tsx --env-file=.env.local scripts/kokyaku-fuyo-points/backfill.ts --from YYYY-MM-DD` で件数と `scripts/kokyaku-fuyo-points/logs/` の CSV を確認する。本反映では環境変数 `KINTONE_ROBOT_AUTH` を設定し、同じコマンドに `--apply` を追加する。通信失敗で止まった場合は、再度確認モードで残件を算出する。
